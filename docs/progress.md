# YOS 开发进度

**这份文件是 YOS 的开发进度节点表和接手须知。**
不管谁来开发，接手第一件事看它，交出前最后一件事更新它。

---

## 维护规矩（不是建议）

1. **每发一个版本，必须在下面的「版本节点表」加一行。**
   这条是机械的：`npm run verify` 会检查表里最新一行的版本号是否等于
   `package.json` 的版本号，对不上**直接报红，发不出去**。
   实现在 `scripts/progress-log.js`，门禁在 `test/progress-log.test.js`。
2. **节点表只写"这一版解决了什么"，一句话。** 展开的改动清单写 `CHANGELOG.md`，
   两边不要互相抄。节点表是让人五分钟看完三个月的，CHANGELOG 是让人查一个具体改动的。
3. **口径、门禁、判据变了，改本文对应小节。** 这些是让新人一天之内不撞墙的东西，
   过期的说明比没有说明更糟。
4. **不要在这里记流水账**（谁哪天干了什么）。这里只记：**货走到哪了、规矩是什么、还欠什么。**

## 接手须知一：三条口径（不看会拿错直觉）

### ① 出货口不是 GitHub

**客户首选取货口 = `https://yoyooai.com/dist/`。** GitHub 两个仓是源码正本，也是镜像缺货或不可用时的备用来源。

- 正常路径优先从我们自己的域名完成装机、升级、组件和依赖下载；镜像缺少目标制品时，
  代码会按既有合同回退到 GitHub。需要证明或强制全程只用镜像时，设置 `YOS_DIST_ONLY=1`。
- 版本目录表 `dist/VERSIONS.md` **不是手写的**，它和货是同一次生成的，数据来自镜像自己的
  `index.json`。所以「最新版本是多少」永远看那一页，不看任何人的记忆，也不看 GitHub Release。
- 钉版本只有一种写法：`install.sh | bash -s -- --branch v0.1.12`。
  `install-v<tag>.sh` 的真实语义是「**那个 tag 时点的安装器**」，直接跑它仍然装最新版。

**对写代码的影响**：任何新的「从 GitHub 下载」路径都会被 `dist-origin*` 一族门禁挡回去。

### ② 组件 = 仓库的子目录

`yos add feishu` 装的是 `yos-components` 仓里的 `channels/001_feishu` 子目录。
装、搜、版本号解析都按这个走。

### ③ OS 是一个整体模块

「OS 内部该拆成必装 / 选装」这条**已经结账不改**（2026-08-09 定）。
渠道和工具各是自己的模块，这个粒度是产品定的，不要再往 OS 里做模块化拆分的提案。

## 接手须知二：会咬人的门禁

**规矩不写在文档里，写成会报红的测试。文档不会让构建失败。**

| 门禁 | 位置 | 撞上会怎样 |
|---|---|---|
| **发版必须更新进度表** | `scripts/progress-log.js` / `test/progress-log.test.js` | 节点表最新一行对不上 `package.json` 的版本 → 红 |
| **测试底线** | `scripts/test-baselines.json` | 通过数少于底线 → 红 |
| **加了测试必须抬底线** | `scripts/test-baseline-policy.js` | 通过数**多于**底线也是红——新测试不进底线就等于没保护 |
| **底线被改动要过审批摘要** | 同上，`approvedDigest` | 偷偷放宽底线 → 红 |
| **关键文件不许删 / 不许清空** | `scripts/critical-test-files.json` | 删掉护栏测试或配置 → 红 |
| **跳过测试要进白名单** | `scripts/test-skip-allowlist.json` | 静默 skip → 红 |
| **计数门禁的判决必须在 `try` 外** | `scripts/verify.js` | 标记和判决都写在 `try` 里，外层包一层 `catch` 就能吞掉整道门禁。<br>现行结构是「gate 只交回计数，判决由调用方在 `try` 外自算」，新写门禁请沿用这个形状 |
| **同一件事只许有一个实现** | `cli/lib/claude-credentials.js` | `cli/` 下任何别的文件再写 `customApiKeyResponses` → 红 |

### 放行标准：150 分线

三条**同时**满足才放行，缺一不放：

1. **行为对** —— 真机实测，不是单测绿了就算。
2. **结构对** —— 改的是病根，不是在症状上贴补丁。
3. **不能被无声撤销** —— 下一个人改坏它，测试必须报红。

第 3 条是这里绝大部分测试的由来。**写完修复请自己拿刀砍一遍**：把调用删掉、
故意长出第二份实现、把判断关掉——**每一刀都必须报红**，否则那些绿是空的。

## 接手须知三：几个判据（照抄，别自己发明）

- **卸载时哪些东西可以删**：判据是 **`~/yos/.env` 里还留着同一个值**，才算我们写的，才删。
  客户改过的一律留下，并在输出里点名说明「这个是你的，我没动」。
  见了就删会毁掉客户在装我们之前自己配好的 Claude。
- **安装来源要落盘**：机器从哪个镜像装的要记下来，升级时读它，不能猜。
- **失败要留出口**：每个可能失败的位置都要给出下一步能做什么，不留死胡同。
- **不要拿一台它根本不用的主机去给安装打分**（`0.1.8` 那条病的教训）。
- **`--yes` 要一路传到底**：说了不问，就真的一个都不问。

## 还欠什么

### 2026-08-11 货架时间口径收口

版本目录展示的是各来源仓提交时间的最大值。该值为可复现构建输入，不是实际发布时刻，界面已明确标为“源码基准时间”。

**一律现查，不要抄快照。** 未解决的产品债列在项目的债务台账里，
本文只点名**会影响你怎么写代码**的几条：

- **两仓 `prepack` 口径相反**（OS 仓与 `yos-components` 仓的处理是反的）——
  **需要定一个统一口径**，这条一直悬着没拍。
- **渠道侧门禁还有能被无声关掉的入口**；OS 侧已机械化，渠道侧的同源锁还没铺完。
- **同一个飞书应用凭据被两台机器同时长连接**时，事件随机落一台，机器人前后自相矛盾，
  而**产品全程不吭声**。配置面已处理，「重复连接要告警」这半条**代码层面没修、没排期**。

**一条要写进来的更正**（免得后来人追一个不存在的问题）：
此前把「守护自愈」一族判为最要命，那是拿 **`0.3.x` 老线**的账推的。
`0.1.12` 起守护和 `yos start` 走的是同一个 `getActiveAdapter().launch()`，
**老线的病根在结构上已经不存在**。这一族需要在新线上重新核过再定性，
不要照着老描述去改。

## 上手命令

```bash
# 取货（客户视角，唯一正确路径）
curl -fsSL https://yoyooai.com/dist/install.sh | bash

# 源码
git clone https://github.com/yoyooai/yos-core.git        # OS 主体
git clone https://github.com/yoyooai/yos-components.git  # 渠道 + 工具

# 全量门禁（放行走的就是这道）
npm ci && npm run verify
```

**标准构建环境**：Linux x64 + Node 22 LTS + npm 10.9.8。
lockfile 提交必须来自这个环境；非标准环境用 `npm ci`，不提交 lockfile 变更。

## 协作规矩

- **作者 ≠ 验收人。** 改动走分支，不直推 `main`；谁写的谁不验收。
- **交互路径必须单独验。** 自动验收环境没有 tty，提问会被静默跳过——
  历史上的「全绿」对这条路是**零覆盖**的。带交互的改动请单独人工验一遍。
