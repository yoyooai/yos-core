# 旧货架回退兼容

## 背景

YOS `0.1.14` 的发布手册要求切换前用当前 `verify-public-shelf.mjs`
全量自审旧货架，并在回退后再次以签字模式核验。生产旧货架是
`0.1.13`，它生成于 `buildId`/能力目录加入之后、`publicationMode`
字段加入之前。当前校验器把这个历史缺字段与新货架被删字段视为同一种
失败，导致旧货架无法生成回退凭据，也无法完成回退后的签字核验。

仓内发布记录保留了生产旧货架证据：874 个实际文件、873 个登记文件，
`index.json` SHA-256 为
`ea64d43821e814c12a7e83e90269dfc7b67e9ab6b1f8ef5d7dd838095b04f9c1`。
当前开发机没有货架机 SSH 权限，未读取或修改生产备份；历史格式依据来自
Git 发布时间线和上述发布记录，不冒充生产原件实测。

## 关键决策

增加显式 `--allow-legacy-missing-publication-mode`，但不把“字段缺失”全局
解释为 production。兼容只在以下条件全部满足时成立：

1. `publicationMode` 必须是缺席，显式 `test-only` 仍拒绝。
2. 最新 Core 标签必须是 `v0.1.13`。
3. `buildId` 必须存在且是 64 位十六进制。
4. 必须执行 `--full`，且只能用于本地备份自审或带完整凭据的 `--signoff`。
5. `index.json` 的逐文件哈希、预期摘要、版本和 provider 校验继续执行。

发布手册只在 `OLD=0.1.13` 时加入该参数。更新版本和正常发布签字不使用它。

## 否掉的方案

- **缺 `publicationMode` 一律按 production**：会让新货架删除字段后也通过，
  等于拆掉现有门禁。
- **手工修改旧货架 `index.json` 补字段**：会改变已发布备份的清单哈希，破坏
  回退证据，且属于不必要的生产修改。
- **跳过旧货架自审/回退签字**：会让“可回退”退化成未验证的文件复制。

## 测试结果

- 默认路径对缺 `publicationMode` 的 0.1.13 继续 fail-closed。
- 显式兼容下，本地全量自审和回退签字通过。
- 新版本缺字段、显式 `test-only`、缺失或伪造 `buildId` 全部拒绝。
- 非本地且非签字路径使用兼容开关，在读取货架前拒绝。
- 手册两处兼容参数均被文档测试锁定为只对 `OLD=0.1.13` 生效。
- 定向测试：63/63 通过；三次撤销变异均精确报红。
- 完整门禁：Jest 426/426、Node 1544/1544、6 个依赖根 0 漏洞。
- 正式包：477 项，内容摘要
  `7e906054002665a41b6c70c00bac860aa7210b4fbd212dd3fd5025ee1235e509`；
  同轮双构建压缩包 SHA-256 一致。
- `npm run verify`：PASS。
