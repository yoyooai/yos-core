# 测试守卫自保护记录

## 背景

自升级回滚测试已经能发现产品代码回退，但原守卫只按标题检查 7 个用例。
把整组改成 `describe.skip`、删除守卫文件或让 Jest 忽略文件时，门禁仍可能报绿。

本轮只加门禁与测试，不修改升级、回滚、运行时、消息或数据行为。

## 关键决策

1. 从 Git 跟踪清单发现全仓测试，不维护一份容易漏项的测试文件列表。
2. 禁止 `skip`、`todo`、`only`、`xit`、`xdescribe` 和 Jest 路径忽略配置。
3. 必须跳过的测试只能进入显式白名单；白名单条目包含原因和提出人，并由摘要防止无声变更。
4. 关键文件清单保护回滚事务测试、旧守卫、发布打包合同和新守卫自身；文件缺失或用例数为 0 都失败。
5. 没有 `.git`、Git 不可用或扫描对象为空时 fail-closed。只测试打包策略的隔离夹具显式注入策略替身，不放宽生产门禁。

否掉的方案：继续增加被点名的测试标题。它仍挡不住整组跳过、文件删除和门禁接线被移走。

## 撤销矩阵

以下 12 种撤销均在一次性本地克隆中被拒绝：

1. `it.skip`
2. `describe.skip`
3. `xit`
4. `it.only`
5. `testPathIgnorePatterns`
6. 删除旧守卫文件
7. 删除 `test/release-pack.test.js`
8. 清空关键测试文件
9. 删除 `.git`
10. 未更新摘要即修改 skip 白名单
11. 把策略失败降级为 warning
12. 把策略检查挪到打包之后

## 边界

仓内守卫可以防止普通回退和误操作，不能防止有权限的人同时删除守卫、测试和外部检查。
合入仍必须依赖受保护分支、固定的 required check 和作者之外的独立验收。

## 通过数底线补强

2026-08-04 增加实际执行数门禁，解决“测试命令退出 0，但只挑中少量用例或全部跳过”仍可能放行的问题：

- Jest 从 JSON 报告读取实际通过数，批准底线为 186。
- Node 测试从 TAP 汇总读取实际通过数，批准底线为 1063，并拒绝 fail、cancelled、skipped 和 todo。
- 底线文件由审批摘要保护；缺失、篡改或擅自降低都会失败。
- 守卫在依赖审计和打包前执行，并由独立接线测试与合成低计数探针保护。
