# 安装来源与目录身份

## 背景

TD-145 与 TD-4② 都属于交付信息失真：官方组件优先从 YOS 分发货架下载，界面却只显示 GitHub；同时，`YOS_DIR` 只要目录存在就可能被普通命令继续使用，即使它属于别的程序。

## 关键决策

- 官方 Registry 解析出的自有组件显示实际生效的分发基址，包含 `YOS_DIST_BASE` 覆盖值；GitHub 保留为“源码仓库”，不再冒充取货口。
- 显式 GitHub 地址、`org/repo` 和第三方 Registry 组件继续显示 GitHub，不把所有来源强行改成自有货架。
- 安装身份使用安装器稳定产出的三项标记共同判断：`.yos/`、`.yos/components.json`、`.claude/skills/`。
- 普通命令遇到“目录存在但零 YOS 标记”时 fail closed，并给出 `unset YOS_DIR` 或重新执行 `yos init` 的修复提示。
- 任一稳定安装标记已经出现时视为安装或恢复正在进行，继续由原命令判断其所需文件；`yos init` 始终豁免，避免修复反过来阻断新装机和既有 add-before-init 合同。

## 未采用

- 不以目录名 `yos` 作为身份。目录名可以任意配置，且不能证明内容属于 YOS。
- 不只检查一个容易碰巧同名的文件；组合标记降低误认无关目录的概率。
- 不把显式 GitHub 安装显示成货架来源；实际下载链不同，不能为了统一文案而说错事实。

## 自动验证

- 官方 Registry、自定义 `YOS_DIST_BASE`、默认货架、显式自有 GitHub 和第三方 GitHub 分别覆盖。
- 真实 `resolveTarget()` 接线测试证明 Registry 路径拿到货架显示，显式 GitHub 路径保持不变。
- 真实 CLI 子进程以无关目录运行 `yos status`，要求非零退出、提示可修复且目录零写入。
- `yos init --help` 在新目录仍正常通过，证明首次安装入口未被守卫拦截。
- 只有 `.claude/skills` 的进行中目录仍允许进入 `add`，防止守卫扩大成对半完成安装的一刀切拒绝。

## 影响范围

只影响组件安装前的来源展示，以及 CLI 进入普通命令前的安装目录身份检查；不修改下载顺序、Registry 内容、安装事务或组件运行逻辑。
